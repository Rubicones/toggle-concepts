## 2. Summary of Changes

**Plain statement on generated 3D models.** No image provider in this codebase can produce a 3D model. Every provider returns raster images only. So I built the resource type, its storage and its loading path, all with the picture as the fallback, but no purchase path produces a model yet. When a provider exists, it should buy the model through the same image ledger and admission path as pictures, then call `storeModel(folder, entry, bytes)`. Until then every model resource shows its picture.

**Code-built scenes (designerVersion 4 drafts):**
- `remotion/director/kit3d.ts` (new). This is a read-only kit copied into version 4 draft workspaces as `./kit3d`. It contains:
  - `Scene3D`, which hosts one canvas and renders exactly one frame. The pixel ratio is fixed at 1, there is no loop and no clock, and `preserveDrawingBuffer` is on so inspection can read the pixels.
  - `seeded(seed)` for randomness and `modelOrPicture`.
  - Model loading through `GLTFLoader` with `delayRender`, falling back to the picture on error.
  - A `final` prop, the designer's plain words for what the final animates.

  The kit holds mechanics only: the designer's `build(THREE, {scene, camera, random})` decides every object, light and camera.
- `apps/local-runner/director/workspace.ts`. The kit is copied for `stage==='draft' && designerVersion>=4`. `writeResources` writes `modelUrl` and adds `modelUrl?:string` to the resources type, for version 4 only. New `storeModel` rejects anything without glTF magic or above 20 MB (`MODEL_NOT_GLB`) and stores the file under `public/<sha256>.glb`.
- `apps/local-runner/director/live-bundle.ts` and `static-assembler.ts`. `kit3d.ts` is treated as generated. The bundle resolver lets exactly `three` and its GLTF loader through for version 4.
- `packages/director/policy.local.ts`. `lintStaticComposition(..., {threeD})` allows exactly `three`. `@react-three/fiber`, `@remotion/three` and animation hooks stay rejected, and the `Math.random` rule still applies. `lintWorkspace` reads `input.json` to decide. `kit3d.ts` is write-protected and skipped by lint.
- `apps/local-runner/director/live-inspect.ts`.
  - The headless browser starts with software WebGL (`INSPECTION_GL_ARGS`, swiftshader) for version 4 only.
  - The settle step waits up to 5 s for `[data-scene3d-pending]` to clear.
  - `.glb` is served as `model/gltf-binary`, and `modelUrl` is added to the asset names.
- `packages/director/layout-inspection.ts`. Each `canvas[data-scene3d]` is read into 32×32 pixels, giving the drawn bounding box and a 4×4 luminance grid. The measured findings are:
  - `RENDER_ERROR` (hard): nothing drew, or WebGL failed.
  - `SUBJECT_CROPPED` (soft): the object is cut by its canvas or by the frame edge.
  - `CONTRAST_OVER_PICTURE` (soft): text over the drawn object has an estimated contrast below 3:1.

## 3. Self-Review & Risk Audit

1. **Frozen `config_hash` / `requestId` / `quoteId`.**
   - Designer versions 1–3 send exactly the same requests: the lint, bundle allow-list, kit, resources type, browser args and stage text are unchanged, and the existing suites pass.
   - Version 4 runs are different. A version 4 run that has not yet sent its designer first turn or opened stage E will now see the `kit-3d` catalogue entry, the extra task clause and the longer stage E mechanics.
   - Conversations already open are not re-sent anything, because the mechanics go once per conversation.
   - No quote digest covers these texts. They are conversation content, not priced configuration.
2. **`DRAFT_INPUT_CAP` and schema size.** `THREE_D_MECHANICS` is under 300 estimated tokens, and the test asserts this. No JSON schema changed, and `agent-output` passes.
3. **`AGENTS.md` principles.**
   - The kit and the mechanics contain no templates, example styles or names.
   - Findings are measured (pixels, bounds, contrast) and the designer authors the scene.
   - No paid calls are made: there is no model purchase path, and the tests use recorded inputs only.
   - Approved copy is not touched.
4. **Other risks.**
   - Software WebGL is slower. Only version 4 inspections get the args, and a render takes about 1 s per view in the test.
   - A `Scene3D` with a broken `build` throws inside React, as any Frame error does, and is reported as a render error.
   - The test frame needs `import React`, which is the same convention as the existing fixtures.
   - Model files over 20 MB are refused.
