## 2. Summary of Changes

**Bulk uploads (problem 1)**
- `lib/brand-upload.ts` (new): uploads three files at a time. Each file is retried automatically up to five times on network errors, 408/409/423/425/429 and 5xx, with backoff. All attempts reuse one request id, so the server's idempotency returns the saved material instead of storing it twice. Permanent errors (unsupported format, too large, material limit, request conflict) stop at once.
- `app/api/studio/campaigns/[id]/brand-intake/route.ts`: changes to `PUT`:
  - It loads the light material projection instead of every file's extracted text. Before, each upload re-read the whole pack, so a drop of N files cost quadratic work.
  - It starts the local worker through the new throttle.
  - Page-preview images can be cached for an hour. They are content-addressed, and the client adds the image digest to the URL.
- `lib/server/local-compute.ts`: new `startLocalWorkflowSoon()`. It spawns the worker on the first call and once more after the burst, instead of one node/tsx process per file.

**Files and roles (problems 2 and 3)**
- `components/studio/brand-files.tsx` + `.module.css` (new): one file panel replaces the "N files" dropdown and the "What each file is" dropdown. It shows:
  - groups by kind (Guidelines, Logos, Fonts, Product & interface, Photos & references, Other, Couldn't open, Not used);
  - a thumbnail for each file: page preview, SVG, font specimen or type icon;
  - reading status per file (Preparing / Ready / Reading n/m / Read / Skipped);
  - a role chip and a Use switch.
  Clicking a file opens its pages, the text the agents receive and a download link.
- Switched-off files take no further part:
  - `materialRoleRows` returns included files only, so the brand card and source priority ignore them.
  - The panel asks nothing about them.
  - When switching a file off fences an active reading (`BRAND_SOURCE_CHANGED`), the page skips that file automatically and reading continues.
- Role questions never block:
  - `usedMaterialRole()` (`packages/brand/material-roles.ts`) uses a guess whenever it is not `unknown`. The local reader (`apps/local-runner/brand-field-analysis.ts`) and `brandRoleOf` use it.
  - The UI shows a guess as a changeable chip, not a question.
- Unreadable files never block reading. A failed file is re-read once automatically. If it fails again, or its format is unsupported, it is switched off and listed under "Couldn't open". Before, `MATERIALS_NOT_READY` stopped the whole read.

**Brandbook step layout** (`brand-intake.tsx`, `brand-field-workspace.tsx`, `brand-field-workspace.module.css`)
- The step has three numbered sections: **Add your files**, **Read the brandbook**, **Check your brand**.
- Files can be dropped anywhere on the step. The large drop area shrinks to a bar once files exist. "Write or paste text" replaces the text dropdown.
- Upload progress shows "Adding n of N…", including how many are retrying. Only files that still failed after the automatic attempts are listed, with "Try these again".
- Reading is one status line with one action. The two big cards and the "Review needed" dead end are gone:
  - Read / Read new files / Pause / Continue / Skip this file and continue;
  - a progress bar;
  - "Spent $x of $y";
  - limits under "Settings".
- Fields are grouped (Name & product, Logo, Colour, Typography, Voice & copy, Imagery & motion, Layout & interface, More). Each collapsed card shows a preview: swatches for colours, the first statement otherwise. Empty fields say the agents will design them. The field total uses the real catalogue size instead of the hard-coded `/28`.
- `brand-fields` GET returns `fields[].preview` from `fieldPreviews()` (`packages/brand/workspace-metrics.ts`), using one bounded query (3,000 rows).

**Questionnaire** (`brief-workspace.tsx` + new `brief-workspace.module.css`, `packages/contracts/brief.ts`)
- Removed "Images for the ads" (MediaDrop and the automatic image selection). The director already reads brand files directly.
- Removed the name, email, delivery date and ad link fields. `briefBlockers` no longer requires them but still validates a value that is present.
- Six numbered sections: The product, Audience and market, Goal and offer, How it should feel, What to make, Rules.
- Optional fields are labelled. Answers prefilled from the brandbook carry a "from brandbook" tag.
- The missing-answers list scrolls to and focuses each field.

## 3. Self-Review & Risk Audit

1. **Frozen digests:** none touched. The questionnaire schema is unchanged. Only blocker rules relaxed, and `buildC1Snapshot` still freezes whatever the draft holds.
2. **`DRAFT_INPUT_CAP` / schema complexity:** agent inputs and provider schemas are unchanged.
3. **AGENTS.md principles:**
   - No paid call is made without the AD. "Read my brandbook" stays an explicit button.
   - The automatic skip only continues an analysis the AD already started and admitted, and skips a file the AD switched off.
   - The automatic re-read of a failed file is local and free.
   - No templates.
   - Approved facts are untouched.
   - Guessed roles may now filter fields a role cannot state, for example copy rules read from a guessed screenshot. The AD can correct the role, and excluded findings come back by including them.
   - Risk: a wrong guess now narrows that file's findings until it is corrected (owner decision: use guesses).
   - Risk: automatically switched-off files can be switched back on; they then block reading again until they open.
