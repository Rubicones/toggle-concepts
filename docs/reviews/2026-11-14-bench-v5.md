### 2.3 Rehearsal findings and fixes

The rehearsal replayed the designer's recorded answers from the export through the fake CLI, with real build and render of the code it wrote there.

- **Works end to end:** ideas → selection → build in the same conversation → render → hero review at the turn cap → stage E → end review. The recorded `previewOptions` mistakes no longer fail the build: the frame rendered on the first build turn (live: no render in twelve turns).
- **The "not reviewed" paths** read correctly on the timeline and in the status, for all three reviews.
- **Found and fixed: an environment fault was sent to the designer as its own problem.** With the renderer's browser missing, twelve turns were answered with "This step needs another attempt: ENOENT …" before the hero stop fired. A missing program or file is now recognised and stops the direction at once with `DRAFT_TOOL_UNAVAILABLE` and a plain question.
- **Found, not changed (wording is covered by the new plan's E1):**
  - The territory is in the digest twice: whole, and again under "Visual direction (in short)".
  - The ideas task repeats three skills the hero stage message already carries (about 5.7k characters).
  - The stage H text says "every means is open" while the digest says the territory's way of making is to be kept.
  - The hero task does not say how many pictures are approved.
  - The reviewer is sent the designer's code sections (variations, brand in code, materials on request) and a role line that speaks of "director or coder".
  - The hero check "Is the call to action read last?" cannot pass on a hero scene without a call to action.

### 2.4 Why the earlier bench misled

The bench runs of 12–13 November were a different pipeline from the one that ran live:

| | Earlier bench | Live run of 14 November |
|---|---|---|
| Designer version | 3 (`runDesigner`, structured turns) | 5 (ideas, chat, stage H and E) |
| Designer model | `claude-sonnet-5-5` by default | Opus |
| Run context | none: the designer instructions and all designer skills as one system prompt | brand pack prefix, skills by stage, positive@1 |
| Brand | a hand-written character and tokens | the stored brand pack and compact sheet |
| Planning | none: scenes and copy written by hand | the real chain; a territory |
| Ideas and selection | none | three ideas, then a build that never saw them |
| `previewOptions` | named in the version 3 instructions | not named anywhere in stage H |
| Reviewer | the same model as the designer, version 1 review | a model with no Local mapping; no review ran |
| Conversation | one session, resumed | two new conversations, then branched |

None of the three causes of the live failure could appear on that bench. The gap is closed for the designer path from the first designer request on. It is still open for everything in the "not covered" table.

### 2.5 What a good bench frame does and does not promise

- **It shows** that the designer path, with the same texts, models, limits and tools, can produce that frame from that input.
- **It does not show** that the planning roles will hand the designer an input of that quality, that the database will admit every request, that a picture will be bought in time, or that the owner's page will say what happened.
- An export-mode run removes the first doubt for one real run. Only a live run removes the others.

## 3. Self-Review & Risk Audit ("Can It Produce Another Bug or Blocking Error?")

1. **Frozen digests:** No request, snapshot or quote changed. The one runner change adds a stop for faults of the computer.
2. **Size limits:** Unchanged.
3. **AGENTS.md principles:** No live or paid call was made. No instruction text was changed.
4. **Risk of the new stop:** `environmentFault` matches `ENOENT`, `EACCES`, `ENOSPC`, a browser that will not launch and similar.
