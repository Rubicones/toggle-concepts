## 2. Summary of Changes

- `components/studio/run-decisions.tsx` + `.module.css` (new): the three AD decisions as visual panels.
  - **Brand check** replaces the raw "Brand alignment" rule list. It shows:
    - the read-only brand card (logos on dark and light, palette, typefaces, product, voice);
    - the rules the agents *added* (colours as swatches, other rules as short statements);
    - the brand sheet pages the agents see.
    One approval follows. The reviewer name is no longer asked; it uses the questionnaire owner, or "Art director".
  - **Scenario choice:** three story cards side by side, each with:
    - the hook and the premise;
    - the first beats, beat count and length;
    - the independent reviewer's verdict;
    - "Choose this story".
  - **Visual looks:** the three visual-direction treatments compared side by side. Each card has:
    - a mood strip (the look's own colours, or the brand palette);
    - the idea;
    - plain-language facets, with a "Compare by" filter (how it is made, composition, colour and light, typography, camera, product in frame, what you see first, motion in the final);
    - the pictures it will make, and the stills that stand in for 3D or video in the draft;
    - the reviewer verdict;
    - **Build this look**, which opens that direction's price in Draft directions. Nothing starts before the price is approved.
- `components/studio/director-workspace.tsx`:
  - new `buildRequest` prop (direction index plus nonce) that requests the quote for one direction;
  - header copy in plain language.
- `components/studio/brand-card.tsx`: `readOnly` mode (no Edit buttons, no pre-submit checks).
- `components/studio/run-step-output.tsx`: the saved Brand step shows the brand card. The agent's raw answer moves into a disclosure.
- `components/studio/guided-run-workspace.tsx` (+ css):
  - Order: current step → steps → brand check → story choice → failures → visual looks → draft directions.
  - Creative focus, the independent review, restart, planning changes, feedback and technical details move to a "Settings and history" section at the bottom.
  - Auto-continue:
    - A running run with no worker online is woken automatically (after 4 s, then every 30 s). An "Starting the studio computer" line replaces the "Continue work" button.
    - Transient local stops (`LOCAL_API_UNAVAILABLE`, `RUN_COORDINATOR_FAILED`) and the `saved_output_recovered` pause are resumed automatically, up to 3 times per page load.
    - A pause the AD made with Stop run, budget stops and build prices still wait for the AD.
- `packages/contracts/guided-run.ts`: step labels and descriptions in plain language:
  - Brand check;
  - Visual looks;
  - Build drafts.
  "Scenarios" keeps its label, because the browser test selects it.
- `app/api/studio/campaigns/[id]/run/route.ts`: when the run is `running` and no worker is online, GET starts the local worker (throttled, `startLocalWorkflowSoon`).
- `apps/local-runner/workflow.ts`: the worker no longer exits after a minute idle while a guided run updated in the last 6 hours is still `running`. That idle exit was what left runs waiting for "Continue work" after the critic sent a step back.
- `lib/server/director-live.ts`: a direction made on another studio computer (a colleague's Local Claude run) has no local workspace folder.
  - The live preview now rebuilds from the direction's sealed iteration source stored in the database.
  - While the other computer is still building, it says so instead of showing an empty preview.

## Addendum: live previews from another studio computer

- **Problem:** a direction in progress on a colleague's computer had no source anywhere but that computer's disk. The fallback above only covered sealed versions.
- `apps/local-runner/director/live-share.ts` (new) + `worker.ts`:
  - Every working preview revision is copied to shared storage, content-addressed at `media/<tenant>/<campaign>/director/live/<hash>.json`.
  - Its key and hash are recorded on the existing `preview:…:ready` event (`detail.liveSource`).
  - A failed upload never stops the work.
- `lib/server/director-live.ts`: without a local workspace, the viewer restores the latest shared revision of the current iteration into `artifacts/m09/remote-live/<direction>/<hash>` (hashes checked by `restoreSavedLiveSource`). If none exists, it falls back to the sealed iteration, then to the "being made on another computer" message.
- **Limitation:** only workers running this code share their source. A run already in progress on older code stays visible only after it seals a version.
- **Risk:** extra storage, one JSON per working revision (bounded by `sourceFiles` limits). No paid calls, no migrations; events stay under the 64 KiB document limit (two short strings added).
- **Verification:** `tsc` and `eslint` on the changed files pass.
