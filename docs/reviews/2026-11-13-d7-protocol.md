# D7 protocol: chat vs. designer version 5 (for the owner and the colleague)

Nothing here is run automatically. The owner runs it; every model call uses the owner's subscription.

## Before you start

1. Apply migrations 20261113000400 (comparisons), 000500 (models), 000600 (skill texts) and 000700 (skill measurement).
2. Leave `STUDIO_DESIGNER_VERSION` unset. Version 5 is the default; `=4` is the way back. Leave `STUDIO_WITHOUT_SKILL` unset.
3. Use the same three briefs as C10: a restrained brand, a product brand and a digital-interface brand. Use the same brand materials.

## Steps, per brief

1. **Chat baseline.** Reuse C10's first-attempt chat picture and its token count. Do not make a new one.
2. **Pipeline.**
   - Start a new shared Local run of the same brief.
   - Approve the brand, choose a scenario and build the looks, without changing any text.
   - Take the **first attempt only**: no revision requests and no reruns.
   - The draft block should say version 5. Its planning shows territories, and its timeline shows "Three ideas for the key frame" and "Chosen: …".
3. **Blind A/B.** On **Chat vs. studio** (`/compare`):
   - create a comparison for this run;
   - add the C10 chat picture and the run's hero frame, plus other scenes if you compared them in C10;
   - judge each pair (A better / B better / about the same, with a note);
   - then "Show which is which".
4. Write the result per pair next to C10's on the same page: C10's comparison stays there, revealed.

## What the app reports, and where (checked: each is produced today)

| Number | Per stage | Total | Where |
|---|---|---|---|
| Requests, turns | yes | yes | `/compare` → "The run in numbers" (C10 `runReport`) |
| Wall time | time per stage | first request to end of last | same |
| Input, cache read, cache write, output | yes | yes | same |
| API-equivalent and cached share | yes | yes | same, and the run's usage panel |
| Critic rounds and stop reasons | hero / end of draft | yes | same page, "Critic rounds: …" (**added in D6**: `criticSummary` from the stored check answers; needs migration 000700) |
| Planning answers that needed a repair turn | planning | yes | same page (C7b) |
| Owner's judgement per pair, against C10 | per pair | score | `/compare`: the D7 comparison and the C10 comparison, both revealed |

Missing before D6: critic rounds and stop reasons. They are now reported from `studio_critic_checks`. Runs made before critic@2, or without the migration, say "not measured".

## Decision rule (from the plan)

If version 5 matches or beats the chat on most pairs, it stays the default (it already is since the D4 follow-up). Otherwise, the review lists per pair where the frame falls short, for the next plan.
