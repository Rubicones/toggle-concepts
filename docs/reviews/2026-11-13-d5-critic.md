## 2. Summary of Changes

**`packages/director/critic-review.ts` (new, pure): one request shape for the hero review, the end review and the selection.**
- **5a, shared criteria.**
  - `stageReviewMaterial(st, stage)` gives the stage's own checks, numbered per skill ("reading-order 2"), and its signs plus the critic stage's signs. The hero review uses `hero`; the end review uses `extension`, kept apart as the D1 notes said.
  - The hard findings are listed as measured.
  - The instruction (`REVIEW_INSTRUCTIONS`) asks for, in order:
    1. a ruling on each earlier note;
    2. a yes/no answer to each check, with one line of evidence;
    3. new notes, each naming its skill and check and saying what to change, why, its priority and its view.
  - A note that contradicts an earlier one names it in `replaces` and says why.
- **5b, memory.** `memoryText` passes the critic's own earlier rounds (check answers and notes with ids `R1N1`…) as text only, with no earlier images. `withAllRulings` gives every earlier note a ruling (missing means "open").
- **5c, bounded rounds.** `reviewStop` applies, in this order:
  - **all-pass:** every check passes, no hard finding is open, and no P0/P1 note; with no checks written, the critic's own acceptance decides;
  - **no-progress:** a round that fixes none of the earlier notes;
  - **rounds:** the second hero round.

  `openPoints` lists what stays open. It goes to the AD (timeline) and into stage E as one note ("OPEN POINTS FROM THE HERO REVIEW … there is no further hero round"), not as another round. `settleHeroReview` combines these steps for one round.
- **5d, independence.**
  - The critic sees the work, the territory (the direction's digest), the brand (run context), the checks and its own history.
  - The hero loop calls `reviewHero(round, shots, findings)`; no designer text can reach it (tested with a marker phrase).
  - Owner decision: the hero review sees the current render at 1,024 px. Earlier rounds are text only.
- **5e, selection mode.** The D4 selection now uses the same request shape:
  - `SELECTION_INSTRUCTIONS` is the shared critic base plus the selection's "what";
  - its context uses the same checks format (`checksText` of the `ideas` stage);
  - it answers per idea, then one choice and a reason.
- **5f, schema.** `critic_review_v2`: rulings, check answers as a compact list `{s, n, ok, e}`, notes `{s, n, priority, view, problem, fix, replaces}`, `accepted`, `summary`. It is 972 characters, well under 2,400.

**Wiring:**
- **`apps/local-runner/director/worker.ts`:**
  - With `critic@2`, the version 4/5 hero review uses the v2 request, keeps `heroMemory`, and returns check marks, rulings, the stop and the open points.
  - The end review uses the same shape with the extension checks and its own `endMemory`. It converts back to the end review's existing note shape, so `runLiveReview` is unchanged.
- **`apps/local-runner/local-claude/transport.ts`:** a critic@2 request does not also get the D1 critic stage message (no duplicate checks or signs).
- **`apps/local-runner/director/hero-chat-loop.ts`:** a stop by rule accepts the hero (`critic`, `no-progress` or `reviews-used`) and puts the open points into the next stage's first message. Without `critic@2`, the earlier behaviour is unchanged.

**5h, UI** (`components/studio/director-timeline.tsx`). Each hero review shows:
- its checks as "✓ … · passed" / "✗ … · not passed";
- earlier notes as "fixed", "still open" or "worse";
- how it ended: "Review finished: all checks passed", "Stopped: no further progress — open points listed", or "Review finished after its rounds — open points listed".

The acceptance line says "when its review stopped making progress (open points listed)".

### D4 follow-up

1. **Version 5 is the default for new shared Local runs.**
   - A run context frozen from now on carries `imageOwner` unless `STUDIO_DESIGNER_VERSION=4` is set, which is the way back. So visual direction writes territories, and `director-start` gives version 5 because it decides by the saved direction's shape.
   - Runs already started, and saved version 4 visual directions, stay version 4.
   - The D4 review's opt-in line is updated.
2. **The designer starts from its own direction, adaptively** (`forkFromDirection` in `packages/agents/local-session.ts`, worker `designerConversation`).
   - **Transport:** forking was already supported: `designerPlan` gives `--resume <planning session> --fork-session`, and a missing conversation restarts once with the full request, which for the designer is the digest seed (C1 behaviour). This is tested with the fake CLI (`nosession`).
   - **The cache question.**
     - The system text is identical across roles: the run context's system is the same bytes for every role, and the designer's role text is in its first message (LC2 layout). So a fork keeps its prefix cache as long as no per-role tool is added.
     - Visual direction sends no `--json-schema` only in contexts with the schema in text (C7b). A visual direction with the old per-role tool would break the cache, so that case uses the digest seed.
   - **The rule.** Fork only when all of these hold:
     - the context has the schema in text;
     - the planning point is under 55 minutes old (the one-hour cache);
     - 0.1 × (conversation − prefix − digest) × hero turns ≤ 1.25 × digest. That is: reading the extra history from the cache on every hero turn costs no more than writing the digest seed once.

     Otherwise, the digest seed.
   - **What this means in practice.** With C9's measured sizes (visual direction about 30k, prefix about 10k, digest about 2.5k, 12 hero turns), the extra history is about 17k × 0.1 × 12 ≈ 20k, against 1.25 × 2.5k ≈ 3k. **The rule chooses the digest seed** unless the visual direction conversation is small (within about 2.6k of prefix plus digest). The fork does happen when it is genuinely cheap.
   - **Messages and timeline.**
     - The first message says "You own treatment concept-n: <name>; the other treatments are not yours", which is needed when forked and harmless otherwise.
     - The timeline says "Continuing from its direction's conversation." or "Started from its direction's summary."
   - Version 4 keeps its planning-branch rule (tested).
