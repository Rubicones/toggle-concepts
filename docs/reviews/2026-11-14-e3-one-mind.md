The direction's premise, creative focus, feeling, goal and audience, and the territory are not sent again.

**The reasons of a new conversation, in plain words.**

| Reason | The timeline says |


### What the bench cannot verify, and what the owner's run shows

The bench has no planning chain, so nothing of E3c runs on it. The rule, the plain words and the continued context are unit-tested. Each hypothesis and the numbers that settle it in a studio run started with `STUDIO_DESIGNER_VERSION=6` and the three chain roles on one model:

| Hypothesis | Confirmed by | Refuted by |
|---|---|---|
| The designer continues the planning conversation. | Timeline: "The designer continues the planning conversation…". The designer's first request line says "branched". | "The designer starts a new conversation…" with its reason. |
| Continuing is cheap when the planning is fresh. | First designer request: cache read near the planning conversation's size (about 65–70k), new input of a few thousand. | Cache read near zero and a write of about 65–70k: the conversation was read again at full price. With the cold-cache sentence in the timeline that is expected (planning older than an hour); without it, it is a defect. |
| The history serves the designer better than a summary. | The owner's judgement of the key frame against run 2 and run 3, and the ideas turn naming things from the strategy and the script that the digest does not hold. | Ideas that ignore the planning, or a first request so long that every hero turn costs more than in a digest run. |
| One model for the chain makes the cache carry over. | Strategy → script → visual direction request lines each read the previous stage from the cache. | Each stage writing the history again (as on 14 November, when two stages ran on Sonnet and one on Opus). |
| Total cost falls. | The run's total against $7.20 on 14 November. The plan's aim is about a third. | A total near or above it. |

**A cost the owner should expect.** Every hero turn of a continued conversation reads the planning history from the cache (about 65k at a tenth of the input price). Over twelve hero turns that is roughly the price of writing 80k tokens once. The earlier rule refused to branch for exactly this reason; the owner chose one mind over that saving.

## 3. Self-Review & Risk Audit ("Can It Produce Another Bug or Blocking Error?")

1. **Frozen `config_hash`, `requestId`, `quoteId` on active runs:** no. Version 5 calls the earlier rule with the earlier (summed) size. The price message gains sentences for shared Local runs; it is not part of a frozen request.
2. **`DRAFT_INPUT_CAP` and schema limits:** a continued first request is larger than a digest request by the planning history, and is admitted only under the same conversation cap as before (120,000). No schema changes.
3. **`AGENTS.md` principles:** no template or look. No paid call. The model a role runs on is shown, not changed.

Risks that remain:

- **The model comparison uses the model the planning request reported.** A planning step stored before this change has it; one without it is treated as another model, and the designer starts a new conversation and says so.
- **The planning history holds three territories**, not only the designer's. The opening still says which one is the designer's and that the others are not.
- **The owner must set the models.** If the chain stays mixed, version 6 works and says in the price message and the timeline that it starts a new conversation.
- **Not verified live.** Everything in the table above is a prediction.
