### Mandatory reasoning correction

The previous correction incorrectly treated the catalog's generic `reasoning` parameter as evidence that reasoning could be disabled. Sonnet 5.5's Chat Completions endpoint rejects `reasoning.enabled=false` with HTTP 400, before generation and with zero cost. Its full catalog metadata explicitly marks reasoning as mandatory and advertises low effort. OpenRouter documents this behavior in its [Claude 5.5 migration guide](https://openrouter.ai/docs/cookbook/evaluate-and-optimize/model-migrations/claude-5-5) and the meaning of [per-model reasoning metadata](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).

The catalog now retains that metadata. Fresh static coder calls use an advertised low effort (or another advertised positive effort if low is absent); missing metadata preserves the model default. They never infer support for disabling reasoning. The adapter transmits effort through `reasoning.effort`, with no unsupported manual thinking budget. All aggregate and per-request token, time and cost ceilings remain unchanged. Low effort is a provider setting, not a guaranteed separate reasoning-token ceiling. Frozen paid/open requests retain their exact settings; the saved zero-cost rejected request is skipped through the existing failed-request retry identity before the corrected request is admitted.

The recorded catalog/rejection fixture and regression tests verify mandatory metadata retention, capability selection, the actual serialized request settings, zero-token/zero-cost accounting for the rejection, no resubmission of its saved receipt, and idempotent reuse of the corrected fixture answer.
